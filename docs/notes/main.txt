# 9. Booking date validation

This:

```python
@field_validator("booking_open_date")
@classmethod
def booking_open_before_departure(cls, v, info):
    departure = info.data.get("departure_date")

    if departure and v >= departure:
        raise ValueError(
            "booking_open_date must be before departure_date"
        )

    return v
```

checks this logical rule:

```text
booking open date < departure date
```

For example:

```text
Booking opens: 10 Aug
Departure:     30 Aug

10 Aug < 30 Aug
```

✅

But:

```text
Booking opens: 30 Aug
Departure:     30 Aug
```

❌

And:

```text
Booking opens: 1 Sep
Departure:     30 Aug
```

❌

# 10. Seats cannot exceed capacity

This validator:

```python
@field_validator("current_seats_booked")
@classmethod
def seats_within_capacity(cls, v, info):
    capacity = info.data.get("capacity")

    if capacity is not None and v > capacity:
        raise ValueError(
            "current_seats_booked cannot exceed capacity"
        )

    return v
```

prevents:

```text
Capacity = 32
Booked = 40
```

because:

```text
40 > 32
```

❌

This is another layer of data validation.

# 18. Error handling

```python

    result = run_prediction(trip_input)
```

If the user gives invalid input:

```python
except ValueError as e:
    raise HTTPException(
        status_code=400,
        detail=str(e)
    )
```

The API returns:

```text
400 Bad Request
```

If there's a bug in your feature pipeline:

```python
except KeyError as e:
    raise HTTPException(
        status_code=500,
        detail=f"Internal feature-building error: {e}"
    )
```

That's:

```text
500 Internal Server Error
```

So:

```text
400 = user's request is wrong

500 = your backend/model code has a problem
```

# 20. Why Step 11 is called a "thin wrapper"

Your comment says:

> `This file is a thin HTTP wrapper around predict.py`

That is exactly right.

You **don't want** to put this inside `main.py`:

```python

# calculate occupancy
# calculate lag
# calculate velocity
# calculate price ratio
# load model
# predict
```

Instead:

```text
main.py
   ↓
API responsibilities

   ↓
ML prediction responsibilities
```

### `main.py`

Handles:

```text
HTTP
↓
validation
↓
request
↓
response
```

### `predict.py`

Handles:

```text
input
↓
feature engineering
↓
XGBoost
↓
prediction
```

That's a clean separation.
